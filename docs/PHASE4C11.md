# Phase 4C.11: Governed customer satisfaction executor (validation gate)

Source: audited `semantic.order_review_evidence_v1`, exactly one row per order; order score is the mean of nonnull *effective* review scores across an order's reviews. Date attribution: `purchase_time` in half-open `[start,end)`.

Registered metric IDs: `average_review_score` (mean score), `low_rating_rate` (low-rating reviewed orders / reviewed orders *100), `review_coverage` (reviewed orders / all eligible orders *100), `reviewed_order_count` (orders). `low_rating` is order score <=2. No SQL is generated by an LLM, and all runtime SQL is strictly compiled from a static template and canonical ISO date strings.

1. Merge `agent/`, `scripts/`, `sql/`, `docs/` into existing project.
2. `python -m scripts.phase4c11_validate` (offline checks).
3. Role inspection (safe, no writes):

```powershell
$dbUser=(docker exec opslens-postgres printenv POSTGRES_USER).Trim()
Get-Content .\sql\phase4c11_role_check.sql -Raw | docker exec -i opslens-postgres psql -X -U $dbUser -d opslens -v ON_ERROR_STOP=1
```

4. Review metric policy and role permissions with project owner. `sql/phase4c11_approval_grant.sql` is a **manual, optional** grant, NOT applied by the package. Reader role must also be allowlisted for this registered source in the MCP server's policy separately. A grant alone does not authorize unrestricted SQL.
5. To smoke test in Python after reader permission and explicit allowlist approval, call `await agent.phase4c11_satisfaction.measure(metric_id,start,end,reader)`, with the existing `mcp_query` callback returning a single aggregate row. For example:

```python
from agent.phase4c11_satisfaction import measure
# result = await measure('average_review_score','2018-06-01','2018-07-01',mcp_reader)
```

**Not completed in this increment:** MCP allowlist integration, live MCP execution, natural-language routing, operational cross-domain joins. No automated grant or registration is performed.

**Important:** The 4C10 source validation was global, not complete period-by-period coverage certification. For empty requested intervals this executor fails closed. It never infers causality. Missing scores are excluded from reviewed population, but all purchase-time eligible orders enter coverage denominator.
