# OpsLens Phase 3G — Provider-Abstracted LLM Planner

Phase 3F proved the dynamic investigation loop. Phase 3G makes the planning intelligence replaceable.

## Boundary

```text
user question
  -> structured investigation state
  -> planner provider
  -> PlannerDecision (Pydantic)
  -> application validator/compiler
  -> governed MCP tool
  -> evidence ledger
  -> next planning turn
```

The LLM does **not** write executable SQL. It proposes an abstract action: action type, hypothesis, evidence needed, rationale, query hint, confidence. The application compiles that into approved MCP calls.

The model therefore cannot invent a new MCP tool, access staging/eval truth, bypass SQL safety, directly change hypothesis states, or stop while core hypotheses remain untested.

## Install and validate

```powershell
pip install -r requirements-phase3g.txt
python scripts/validate_phase3g.py
```

Expected:

```text
Checks passed: 8/8
VERDICT: PASS
```

The required validator uses `FakePlannerProvider`, so no API key is needed. It validates the same typed provider contract used by a real model.

## Optional real OpenAI provider

The included `OpenAIResponsesPlannerProvider` uses the Responses API with strict JSON-schema output.

```powershell
$env:OPENAI_API_KEY="..."
$env:OPSLENS_PLANNER_MODEL="gpt-6-luna"
python scripts/smoke_phase3g_openai.py
```

The model is environment-configurable; OpsLens is not architecturally tied to one model.

## Why this phase matters

```text
reasoning is replaceable
control is not
```

After this phase, the next work should focus on planner recovery, conflicts/incomplete evidence, abstention, and trajectory-level evaluation rather than adding unnecessary autonomy.
