# OpsLens Phase 3E v2 — Circular-import fix

The original Phase 3E created this dependency cycle:

```text
mcp_server.server
    -> retrieval.hybrid
        -> agent.mcp_bridge
            -> mcp_server.server
```

That is invalid because the MCP server is imported again before its `mcp`
object has finished initializing.

The corrected architecture is:

```text
                    +-----------------------+
                    | LangGraph / agent     |
                    +-----------+-----------+
                                |
                                | MCP Client
                                v
                    +-----------------------+
                    | mcp_server.server     |
                    | search_knowledge      |
                    +-----------+-----------+
                                |
                                | direct controlled call
                                v
                    +-----------------------+
                    | retrieval.hybrid      |
                    +-----------+-----------+
                                |
                                | read-only runtime engine
                                v
                    +-----------------------+
                    | PostgreSQL / pgvector |
                    +-----------------------+
```

`retrieval.hybrid` now imports only the read-only `engine` from
`mcp_server.runtime_tools`.

It does NOT import:
- `agent.mcp_bridge`
- `mcp_server.server`

This keeps the server-side retrieval implementation below the MCP protocol
boundary, while application/agent code continues to call it through MCP.

## Apply

Replace:

```text
retrieval/hybrid.py
```

with the supplied file.

Then run the import diagnostic:

```powershell
python scripts/validate_phase3e_imports.py
```

Expected:

```text

[PASS] mcp_server.server imports without circular dependency
[PASS] LangGraph Phase 3E imports successfully

```

Then run the real integration test again:

```powershell
python scripts/validate_phase3e.py
```
