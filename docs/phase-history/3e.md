# OpsLens Phase 3E — MCP Retrieval + LangGraph Tool Routing

Phase 3D proved retrieval quality.

Phase 3E promotes hybrid retrieval into a first-class MCP tool and connects it
to the LangGraph investigation workflow.

## Architecture

```text
LangGraph investigation
        |
        v
 evidence request router
        |
   +----+-------------------+
   |                        |
   v                        v
structured evidence      knowledge evidence
run_readonly_sql         search_knowledge
   |                        |
   +----------- MCP --------+
               |
               v
       normalized evidence
               |
               v
        evidence ledger
               |
               v
       hypothesis update
```

## MCP tools

The OpsLens MCP server now exposes seven governed tools:

1. `discover_domains`
2. `discover_schema`
3. `describe_relation`
4. `list_metrics`
5. `get_metric_definition`
6. `run_readonly_sql`
7. `search_knowledge`

## Important semantic distinction

A retrieved document can **corroborate** a causal hypothesis.

A document does not automatically prove causality.

In the Phase 3E validation:
- H1 receives structured SQL evidence plus document corroboration.
- H2 receives a campaign document and is marked `CORROBORATED`, not `SUPPORTED`,
  because this graph has not yet run its structured marketing-cost test.

That distinction is deliberate.

## Security

`search_knowledge`:
- uses the governed chunk table;
- combines dense and lexical retrieval;
- applies reranking;
- filters prompt-injection chunks;
- remains behind the same MCP boundary as SQL.

Retrieved document text is evidence data, not instructions.

## What comes next

After Phase 3E passes, the next meaningful milestone is the true iterative
investigation loop:

```text
plan
  ↓
choose next hypothesis
  ↓
choose SQL / retrieval evidence
  ↓
execute through MCP
  ↓
update evidence ledger
  ↓
supported / weak / rejected / conflicting
  ↓
is evidence sufficient?
  ├─ no → choose next test
  └─ yes → conclude
```

At that point we can introduce a provider-abstracted LLM planner while keeping
the application in control of permissions, budgets, stop conditions and
evidence semantics.
