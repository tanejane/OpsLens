# OpsLens Phase 3F — Dynamic Natural-Language Investigation Loop

Phase 3E proved that LangGraph could route predetermined evidence requests.

Phase 3F removes the predetermined request list.

## New flow

```text
user question
    |
    v
understand_question
    |
    v
plan_next
    |
    +----------------------------+
    |             |              |
 metric tool    SQL tool     knowledge tool
    |             |              |
    +-------------+--------------+
                  |
                  v
               assess
                  |
                  v
          check sufficiency
             |         |
             no        yes
             |          |
             +--> plan  +--> final
```

## Natural-language interpretation

The baseline parser can map variants such as:

```text
Why did profit drop even though sales went up?
Sales increased but profitability got worse. What caused it?
为什么营收上升但是利润下降？
```

into the same structured intent:

```text
intent: root_cause_investigation
primary_metric: contribution_profit
comparison_metric: revenue
```

This deterministic parser is a test baseline, not the final intelligence layer.

## Dynamic policy

There is no initial R1/R2/R3 request list.

`DynamicInvestigationPolicy.choose_next(state)` looks at:
- which evidence already exists;
- which hypotheses remain unresolved;
- which type of evidence is required next.

It then proposes the next governed MCP action.

## Why we still use a deterministic planner here

We need to know that:
- loops terminate;
- budgets work;
- evidence order is sensible;
- tool routing works;
- hypothesis semantics remain correct;

before introducing LLM variability.

The next planner can implement the same `choose_next(state)` interface using
structured model output.

## Application remains in control

Even after an LLM planner is added, it will not own:
- database permissions;
- available MCP tools;
- tool-call budgets;
- stop conditions;
- evidence state transitions;
- human approval requirements.
