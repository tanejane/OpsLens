# OpsLens Phase 2C — Semantic Metrics + Safe SQL Contracts

This phase creates the business contract between the runtime data world and the future MCP/agent layer.

## Why this exists

A production investigation agent should not receive:
- the entire database schema in every prompt,
- direct access to staging,
- hidden evaluation truth,
- unrestricted SQL,
- undefined business metrics.

Instead, OpsLens exposes controlled discovery and read-only query contracts.

## Files

```text
config/metric_catalog.json
requirements-phase2c.txt
scripts/phase2c_semantic_tools.py
```

## Tools implemented

- `discover_domains()`
- `discover_schema(domain)`
- `describe_relation(schema, relation)`
- `list_metrics(domain=None)`
- `get_metric_definition(metric_name)`
- `run_readonly_sql(query, purpose, expected_grain, max_rows, timeout_ms)`

## SQL safety policy

The generic SQL tool:
- accepts exactly one query,
- permits read-only query ASTs only,
- blocks INSERT/UPDATE/DELETE/DDL,
- requires schema-qualified relation names,
- blocks `staging`,
- blocks system catalogs,
- allows canonical/semantic schemas only,
- applies a hard outer row cap,
- applies a PostgreSQL statement timeout,
- requires `purpose` and `expected_grain` for later trace/eval scoring.

Schema discovery uses controlled internal metadata queries rather than giving the model unrestricted `information_schema` access.

## Important data-world rule

GA4 and Olist are separate business environments.
Do not fabricate user/customer joins between them.
