# OpsLens Phase 3A — Investigation State + Control Loop

This phase starts the investigation brain.

It intentionally does **not** connect an LLM yet. The goal is to prove that application-owned control, state, budgets, hypothesis lifecycle, and evidence stopping rules work independently from model quality.

## Why LangGraph here

LangGraph is appropriate for OpsLens because the workflow is long-running, stateful, and mixes deterministic control with later agentic decisions. Current LangGraph guidance emphasizes shared state, nodes/edges, durable execution, persistence, and human-in-the-loop for this class of workflow.

## State

OpsLens now carries explicit investigation state:

```text
question

plan

evidence_ledger

```

Hypotheses have explicit states:

```text
UNTESTED
TESTING
SUPPORTED
WEAK
REJECTED
CONFLICTING
```

## Graph v1

```text
START
  |
initialize
  |
plan
  |
select_hypothesis
  |
check_evidence
  |              \
continue_stub     finalize
  |                 |
  +----loop----------+
                    END
```

`continue_stub` is deliberate. Phase 3A validates control flow only.

Phase 3B will replace that stub with:
- model-driven planning/refinement,
- MCP tool selection,
- evidence extraction,
- hypothesis updates.

## Important design rule

The LLM will be allowed to propose:
- hypotheses,
- evidence requests,
- next tests,
- interpretations.

The application retains control over:
- budgets,
- allowed tools,
- permissions,
- stop conditions,
- human approval requirements,
- whether conflicting evidence blocks finalization.
