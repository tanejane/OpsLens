# OpsLens Phase 2D — MCP Server

Phase 2D turns the governed business contracts from Phase 2C into a real MCP server.

The server deliberately remains a **tool/data access boundary**, not the investigation brain.
LangGraph orchestration comes after this phase.

## Architecture

```text
Future LangGraph investigation agent
                |
                | MCP
                v
OpsLens Business Investigation MCP
                |
     -------------------------
     |     governed tools    |
     -------------------------
       |        |         |
    metrics   schema     safe SQL
                         |
                         v
                PostgreSQL runtime
                         |
              canonical/semantic
```

## MCP tools

- `discover_domains`
- `discover_schema`
- `describe_relation`
- `list_metrics`
- `get_metric_definition`
- `run_readonly_sql`

The official MCP Python SDK generates the input schemas from Python type hints.

## Production-style security boundary

The MCP server does **not** use `opslens_admin`.

It uses a dedicated PostgreSQL login:

```text
opslens_mcp_reader
```

That role:
- has SELECT/USAGE only on approved canonical/semantic schemas,
- has no staging access,
- has no observability access,
- defaults to read-only transactions,
- has a 5-second PostgreSQL statement timeout.

The SQL tool then adds a second application-level boundary:
- AST validation,
- one statement only,
- SELECT/query only,
- schema-qualified relations,
- approved schemas only,
- hard row cap,
- per-call timeout,
- mandatory investigation purpose,
- mandatory expected grain.

This is intentional defense in depth.

## Install

From the project root:

```powershell
pip install -r requirements-phase2d.txt
```

## Configure runtime database identity

Copy the Phase 2D env values into your existing `.env`.

For local development you may use:

```text
MCP_DB_USER=opslens_mcp_reader
MCP_DB_PASSWORD=opslens_mcp_local_dev
MCP_DATABASE_URL=postgresql+psycopg://opslens_mcp_reader:opslens_mcp_local_dev@localhost:5432/opslens
```

For anything deployed, use a generated secret rather than the local-dev password.

Then run:

```powershell
python scripts/setup_phase2d_runtime_role.py
```

## Validate the actual MCP protocol boundary

```powershell
python scripts/validate_phase2d_mcp.py
```

Expected:

```text
Checks passed: 6/6
VERDICT: PASS
```

The validation uses the official MCP client in-memory against the real server object, so it tests MCP tool registration and calls rather than calling the implementation functions directly.

## Optional MCP Inspector

The current SDK CLI can launch the server for interactive inspection:

```powershell
mcp dev mcp_server/server.py
```

## Deployment direction

For local development, stdio/in-memory testing is sufficient.

When OpsLens is deployed later, use Streamable HTTP behind authentication rather than inventing a proprietary tool protocol.
